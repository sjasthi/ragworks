About the Project

RAGWorks

A Retrieval-Augmented Generation system that lets users upload documents and get grounded, source-referenced responses from an LLM.

Ashley Haxton Elijah Nicholson Ricardo Martinez
01 — Overview

What is RAG?

This project uses RAG at its core. RAG in a nutshell:

  • Retrieve — find relevant information from uploaded documents
  • Augment — pass the retrieved information and the user query to the LLM
  • Generate — LLM uses the knowledge to generate a context-aware response to provide to the user
02 — RAG Architecture

System Components

RAGWorks is split into three main components:

01

Document Ingestion

Accepts various file types, including HTML, DOCX, TXT, PDF, and PPTX. Files are parsed into plain text and split into overlapping chunks (800 chars, 150 char overlap).

02

Embedding & Storage

Chunks are converted to vectors via OpenAI embeddings and stored in ChromaDB. MySQL unifies content and shares embeddings amongst users on different local machines.

03

Retrieval & Generation

User queries are embedded and matched against ChromaDB via vector similarity search. The top-k chunks and user query are bundled together into a context string and passed to the LLM for answer generation.

03 — Flow

Query Pipeline

User Query
→
Embed Query
→
Vector Similarity Search
→
Retrieve Relevant Context
→
Pass Context and User Query to LLM
→
Answer Generation
04 — Conclusion

Key Benefits to this RAG System

Reduces Hallucination

Answers are grounded in real documents with source references, reducing the risk of LLM hallucination.

Control Over the Data

The system only uses information from the uploaded documents to answer queries, giving a better level of control over what the LLM knows and references.
